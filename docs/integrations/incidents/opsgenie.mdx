<Warning>
Opsgenie shuts down on **April 5, 2027**. Atlassian ended new sales and signups
on June 4, 2025. Complete your migration before shutdown; Atlassian says access
will end and unmigrated data will be deleted. See the
[official timeline](https://www.atlassian.com/software/opsgenie/pricing) and
[migration resources](https://www.atlassian.com/software/opsgenie/migration).
</Warning>

OpenSRE's OpsGenie integration is **maintenance-only** for existing users during
migration. New deployments should choose a supported incident platform. Existing
configuration, verification, and alert tools remain available during the
transition; this notice does not disable them.

## Migration checklist

1. Assign a migration owner and choose a cutover date before April 5, 2027,
   leaving time to test alert delivery and roll back before shutdown.
2. Inventory alert sources, routing rules, escalation policies, on-call schedules,
   API consumers, and runbooks. Follow Atlassian's migration resources if moving
   to Jira Service Management, or your chosen provider's migration guide.
3. Migrate or export the incident history and configuration you need to retain
   before Opsgenie becomes inaccessible.
4. Configure and verify the replacement connection in OpenSRE separately. Do not
   assume OpsGenie credentials or tools work with the replacement. OpenSRE's
   existing [PagerDuty](/integrations/incidents/pagerduty) and
   [Incident.io](/integrations/incidents/incident_io) guides describe those options;
   they are not automatic migration paths.
5. Test a representative alert through routing, paging, acknowledgement, and
   investigation in OpenSRE. Keep the existing OpsGenie connection until the
   replacement is validated.
6. After cutover, remove the OpsGenie record with
   `opensre integrations remove opsgenie`, remove `OPSGENIE_API_KEY` and
   `OPSGENIE_REGION` from your environment or secret manager, and revoke the old
   API key. If connected through OpenSRE Cloud, also disconnect OpsGenie at
   **app.opensre.com → Integrations**. Update runbooks that call `opsgenie_alerts`
   or `opsgenie_alert_detail`.

## Overview

OpenSRE queries OpsGenie for active alerts and alert details so the agent can
correlate on-call incidents with infrastructure events.

There is **no** `opensre integrations setup opsgenie` handler today. Configure OpsGenie
with environment variables or the integration store, then verify with
`opensre integrations verify opsgenie`.

## Prerequisites

- Existing OpsGenie account (new signups have ended)
- API key with read access

## Setup

### Option 1: Environment variables

```bash
OPSGENIE_API_KEY=your-api-key
OPSGENIE_REGION=us   # or "eu" for EU accounts
```

| Variable | Default | Description |
| --- | --- | --- |
| `OPSGENIE_API_KEY` | — | **Required.** OpsGenie API key |
| `OPSGENIE_REGION` | `us` | Region: `us` or `eu` |

### Option 2: Persistent store

```json
{
  "version": 1,
  "integrations": [
    {
      "id": "opsgenie-prod",
      "service": "opsgenie",
      "status": "active",
      "credentials": {
        "api_key": "your-api-key",
        "region": "us"
      }
    }
  ]
}
```

## Credentials

1. In OpsGenie, go to **Settings** → **API key management**
2. Click **Add new API key**
3. Name it `opensre` and enable **Read** access
4. Copy the key

<Info>
EU accounts use a different endpoint. Set `OPSGENIE_REGION=eu` if your OpsGenie URL
is `app.eu.opsgenie.com`.
</Info>

## Tools

| Tool | What it does |
| --- | --- |
| `opsgenie_alerts` | List and search active OpsGenie alerts |
| `opsgenie_alert_detail` | Fetch full detail for one alert by ID |

Run `opsgenie_alerts` first to find an alert ID, then call `opsgenie_alert_detail`
when you need deeper context.

## Verify

```bash
opensre integrations verify opsgenie
```

Expected output:

```
Service: opsgenie
Status: passed
Detail: Connected to OpsGenie (US region); API key accepted.
```

## Troubleshooting

| Symptom | Fix |
| --- | --- |
| **401 Unauthorized** | Check the API key and confirm it has Read access |
| **404 Not Found** | Set `OPSGENIE_REGION=eu` if you use the EU instance |
| **Rate limited** | OpsGenie enforces per-minute limits — reduce query frequency |
| `opensre integrations setup opsgenie` | Not available — use env vars or the store |

## Security

- Use a **read-only API key** — OpsGenie supports granular permission scopes.
- Store the API key in `.env` or your secret manager — not in source control.
