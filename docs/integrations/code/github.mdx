## Overview

OpenSRE connects to GitHub so the agent can work with issues, pull requests, repositories, Actions, and code — and correlate recent commits with incidents.

Once GitHub is connected, the interactive-shell **action agent** uses **`github_cli`** (authenticated `gh`) for flexible reads and writes — create/list/view issues and PRs, assign, label, comment, merge, search, releases, workflow runs, and `gh api` — without a separate approval gate. Prefer this over shell `gh` / `!gh`. These requests stay on the action path (not the conversational gather/answer loop).

| Area | How OpenSRE does it |
| --- | --- |
| Ad-hoc issues, PRs, repos, search, API | `github_cli` (action agent) |
| Engineering digests, PR readiness, security alerts | [GitHub workflow tools](/integrations/code/github-workflow-tools) |
| Security and quality fixes and PRs | [GitHub security and quality fix](/integrations/code/github-security-fix) |
| Failing CI fixes and branch pushes | [GitHub CI fix](/cicd/github-ci-fix) |
| Slack → GitHub issue create/update/close | Propose + approve via workflow mutation tools |
| Code, commits, files, issue search | Dedicated GitHub tools |
| Failed deploys / workflow runs | [GitHub Actions tools](/integrations/code/github-actions) |
| Organization-owned incident runbooks | [Runbook-guided investigations](/integrations/incidents/runbook-guided-investigations) |

## Prerequisites

- GitHub account with repository access
- One of: browser sign-in (recommended), a personal access token, or GitHub Copilot MCP access
- For chat `github_cli`: the `gh` binary on `PATH` (OpenSRE supplies the token). If it is missing, follow the [GitHub CLI installation guide](https://cli.github.com/).

## Setup

### Option 1: Connect in the OpenSRE web app (recommended for teams)

1. In the web app, open **Settings → GitHub** and click **Connect GitHub**. Approve OpenSRE on GitHub.
2. Everyone in the workspace now shares this connection: the hosted agent in Slack and Telegram uses it, and each signed-in CLI picks it up automatically.
3. Your CLI syncs the connection when you sign in (`opensre account login`) and each time the interactive shell starts. After you change it in the web app, run `opensre integrations sync` (or `/integrations sync` in the shell) to pick it up right away.

A GitHub setup you did yourself on a machine always wins over the workspace connection. To switch that machine to the workspace connection, run `opensre integrations remove github`, then `opensre integrations sync`.

### Update GitHub permissions

When the agent hits a repository or organization it cannot reach, it stops and tells you exactly what to do, with a link:

| What the agent says | What to do |
| --- | --- |
| The organization has not approved OpenSRE | Open the link, find the organization under **Organization access**, and click **Grant** (or **Request** if you are not an owner) |
| The organization requires SAML single sign-on | Open the link and authorize OpenSRE for that organization |
| The connection is missing a permission, or the token was revoked | Click **Reconnect** in **Settings → GitHub** (or run `/integrations setup github`) and approve the new permissions |
| The repository is not covered | Grant OpenSRE access to the repository's owner at the link |

**Settings → GitHub → Update permissions** opens the same GitHub page at any time. Then ask the agent to retry.

The hosted agent picks up a new or changed GitHub connection within a minute. If it still cannot reach GitHub, click **Sync to agent** in **Settings → GitHub**.

### Option 2: Interactive CLI (browser sign-in)

```bash
opensre integrations setup github
```

In the interactive shell, use `/integrations setup github` or ask “Can you configure GitHub for me?”

If your workspace already has GitHub connected in the web app, setup offers to use that connection instead of a separate sign-in. If it does not, setup offers to share your connection with the workspace so the hosted agent in Slack and Telegram can use GitHub too.

1. Choose **Sign in with GitHub**. OpenSRE opens GitHub's device authorization page and prints a one-time code. Enter the code and approve OpenSRE; no personal access token is required.
2. OpenSRE discovers your account and checks repository access. If GitHub or your organization has not granted access yet, approve it and retry the check without restarting setup.
3. OpenSRE saves the verified connection and reports the signed-in account and repository access. Press Ctrl+C to cancel at any point.

This uses GitHub's OAuth device flow, which has no client secret. The public OAuth App client id ships with OpenSRE; override it with `OPENSRE_GITHUB_OAUTH_CLIENT_ID` if you register your own app.

If you prefer, the same prompt lets you **paste a token (PAT)** instead.

### Option 3: Environment variables

```bash
GITHUB_MCP_AUTH_TOKEN=ghp_your_personal_access_token
GITHUB_MCP_URL=https://api.githubcopilot.com/mcp/   # default
GITHUB_MCP_MODE=streamable-http                      # default
GITHUB_MCP_TOOLSETS=repos,issues,pull_requests,actions  # default
```

| Variable | Default | Description |
| --- | --- | --- |
| `GITHUB_MCP_AUTH_TOKEN` | — | GitHub personal access token. Required unless you authorize in the browser (Option 1) |
| `GITHUB_TOKEN` / `GH_TOKEN` | — | Alternate token env names also accepted by `github_cli` and some workflow tools |
| `GITHUB_MCP_URL` | `https://api.githubcopilot.com/mcp/` | GitHub MCP server URL |
| `GITHUB_MCP_MODE` | `streamable-http` | Transport mode: `streamable-http`, `sse`, or `stdio` |
| `GITHUB_MCP_TOOLSETS` | `repos,issues,pull_requests,actions` | Comma-separated toolsets to enable |
| `GITHUB_MCP_COMMAND` | — | Command to run (required for `stdio` mode only) |
| `GITHUB_MCP_ARGS` | — | Space-separated args for `stdio` mode |
| `OPENSRE_GITHUB_OAUTH_CLIENT_ID` | _(built-in)_ | OAuth App client id for browser sign-in (device flow). Override to use your own app |

## Credentials

### Creating a personal access token

1. Open [New fine-grained personal access token](https://github.com/settings/personal-access-tokens/new).
2. Name it **OpenSRE**, choose an expiry, and select the owner and repositories OpenSRE may use.
3. Grant read access to Contents, Metadata, Issues, Pull requests, and Actions. Add write access only for operations you want OpenSRE to perform.
4. Generate and copy the token. If your organization requires approval, approve the token before retrying setup.

<Info>
For GitHub Enterprise Server, set `GITHUB_MCP_URL` to your enterprise MCP endpoint.
</Info>

### Transport modes

| Mode | When to use |
| --- | --- |
| `streamable-http` | Default. Works with GitHub Copilot MCP and most hosted instances |
| `sse` | For older MCP servers using Server-Sent Events |
| `stdio` | For running a local MCP server process (`npx @modelcontextprotocol/server-github`) |

## Verify

```bash
opensre integrations verify github
```

Expected output:

```
Service: github
Status: passed
Detail: GitHub MCP validated for your-username; discovered 18 tools including repository source helpers
```

Inside the REPL: `/integrations verify github` or `/verify github`. Alias: `github_mcp`.

## Troubleshooting

| Symptom | Fix |
| --- | --- |
| **Authentication failed** | Check that the token has `repo` scope and is not expired |
| **Required tools missing** | Ensure toolsets include `repos` — it provides `get_file_contents`, `list_commits`, etc. |
| **`github_cli` fails / gh not found** | Install [GitHub CLI](https://cli.github.com/) so `gh` is on `PATH`; confirm token via verify |
| **Connection refused** | Verify `GITHUB_MCP_URL` is reachable and the MCP server is running |
| **Connected in the web app, but the CLI does not see it** | Run `opensre integrations sync`. If it says this machine keeps its own GitHub setup, remove that setup first |
| **Browser sign-in unavailable** | Set `OPENSRE_GITHUB_OAUTH_CLIENT_ID` to a device-flow-enabled OAuth App, or fall back to pasting a PAT |

## Security

- Prefer the **least privilege** that matches how you use OpenSRE (read-only if you only ask questions; write scopes if you want chat to create/edit issues and PRs).
- Limit token scope to the repositories OpenSRE needs.
- Store the token in `.env`, not in source code.
