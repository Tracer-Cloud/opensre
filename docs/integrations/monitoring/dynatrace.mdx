---
title: "Dynatrace"
description: "Connect Dynatrace Grail so OpenSRE can retrieve bounded service and Kubernetes logs"
---

OpenSRE queries recent logs from Dynatrace Grail using generated, read-only DQL. The integration supports Kubernetes deployment, namespace, container, enriched service name, log-level, and content-text filters.

## Prerequisites

- A Dynatrace environment with Grail log access
- A platform token with `storage:buckets:read` and `storage:logs:read`
- A successful `fetch logs | limit 1` query in a Dynatrace Notebook

## Setup

### Interactive CLI

```bash
opensre integrations setup dynatrace
```

Enter the tenant origin, such as `https://abc12345.apps.dynatrace.com`, and the platform token.

### Environment variables

```bash
DYNATRACE_TENANT_URL=https://your-environment.apps.dynatrace.com
DYNATRACE_PLATFORM_TOKEN=your-platform-token
```

| Variable | Description |
| --- | --- |
| `DYNATRACE_TENANT_URL` | **Required.** HTTPS tenant origin ending in `.apps.dynatrace.com` |
| `DYNATRACE_PLATFORM_TOKEN` | **Required.** Bearer platform token with Grail bucket and log read permissions |

Do not include `/ui`, `/platform`, query parameters, or a trailing application path in the tenant URL.

## Verify

```bash
opensre integrations verify dynatrace
```

Verification executes a five-minute, `0.1` GB scan-limited log query and returns successfully even when the selected period contains no logs.

## Log retrieval

The `query_dynatrace_logs` tool accepts structured filters and generates DQL similar to:

```text
fetch logs, from: -15m, scanLimitGBytes: 1
| filter matchesValue(k8s.deployment.name, "omnenest*")
| sort timestamp desc
| fields timestamp, loglevel, content, service.name, dt.service.name, k8s.namespace.name, k8s.deployment.name, k8s.container.name, host.name
| limit 100
```

For Kubernetes workloads, prefer `deployment_name` or `container_name`. `service.name` may be absent unless log enrichment has populated it.

## Safety limits

- Queries are read-only and generated by OpenSRE; arbitrary DQL is not accepted.
- Lookback is capped at 24 hours.
- Results are capped at 200 records.
- Every query uses `scanLimitGBytes: 1` and a 20-second client timeout.
- The platform token is injected from resolved integration state and is never accepted as a model-controlled filter.

## Troubleshooting

| Symptom | Fix |
| --- | --- |
| `401` or `403` | Confirm the token is active and has `storage:buckets:read` plus `storage:logs:read` |
| Tenant URL rejected | Use only the tenant origin, for example `https://abc123.apps.dynatrace.com` |
| Query returns no service names | Filter with `k8s.deployment.name` or `k8s.container.name`; service enrichment may be missing |
| Query times out | Narrow the timeframe and add deployment, namespace, or container filters |
