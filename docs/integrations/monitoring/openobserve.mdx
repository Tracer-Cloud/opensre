## Overview

OpenSRE connects to OpenObserve to retrieve read-only log, metric, and trace evidence when an alert fires. It can also discover streams before querying, helping correlate errors, anomalies, and service activity during incidents.

## Prerequisites

- An OpenObserve instance (self-hosted or cloud-hosted)
- The URL of your OpenObserve deployment
- Either an access token **or** a username and password
- Access to the organization you want OpenSRE to query

## Setup

There is no `opensre integrations setup openobserve` handler. Configure OpenObserve with environment variables or the persistent store only.

### Option 1: Environment variables

Add to your `.env`:

```bash
OPENOBSERVE_URL=https://openobserve.example.com
OPENOBSERVE_TOKEN=your_access_token
OPENOBSERVE_ORG=default
OPENOBSERVE_STREAM=logs
OPENOBSERVE_TRACE_STREAM=traces
OPENOBSERVE_MAX_RESULTS=100
```

| Variable | Default | Description |
| --- | --- | --- |
| `OPENOBSERVE_URL` | — | **Required.** URL of your OpenObserve instance |
| `OPENOBSERVE_TOKEN` | — | Authentication token (use **or** username/password) |
| `OPENOBSERVE_USERNAME` | — | Username when not using a token |
| `OPENOBSERVE_PASSWORD` | — | Password when not using a token |
| `OPENOBSERVE_ORG` | `default` | Organization name |
| `OPENOBSERVE_STREAM` | *(empty)* | Optional default stream for log queries and trace-stream fallback |
| `OPENOBSERVE_TRACE_STREAM` | *(empty)* | Optional trace-specific stream; overrides `OPENOBSERVE_STREAM` |
| `OPENOBSERVE_MAX_RESULTS` | `100` | Configured maximum number of results returned |

For traces, `OPENOBSERVE_TRACE_STREAM` takes precedence over `OPENOBSERVE_STREAM`; when both are empty, the trace tool uses `traces`. Every tool also enforces a hard cap of 200 returned records, even when `OPENOBSERVE_MAX_RESULTS` is higher.

#### Alternative authentication

If your deployment uses username/password instead of a token:

```bash
OPENOBSERVE_URL=https://openobserve.example.com
OPENOBSERVE_USERNAME=your_username
OPENOBSERVE_PASSWORD=your_password
OPENOBSERVE_ORG=default
```

Use **either** `OPENOBSERVE_TOKEN` **or** `OPENOBSERVE_USERNAME` + `OPENOBSERVE_PASSWORD`. Verify requires the URL plus one of those auth pairs.

### Option 2: Persistent store

```json
{
  "version": 1,
  "integrations": [
    {
      "id": "openobserve-prod",
      "service": "openobserve",
      "status": "active",
      "credentials": {
        "base_url": "https://openobserve.example.com",
        "api_token": "your_access_token",
        "org": "default",
        "stream": "logs",
        "trace_stream": "traces",
        "max_results": 100
      }
    }
  ]
}
```

Store credentials use `base_url` and `api_token` (not `url` / `token`). For username/password auth, set `username` and `password` instead of `api_token`.

## Credentials

1. Log in to your OpenObserve instance
2. Open user or organization settings
3. Create or retrieve an access token
4. Copy your OpenObserve URL
5. Note the organization name you want OpenSRE to query
6. Add these values to your OpenSRE configuration

## Tools

| Tool | Use it for |
| --- | --- |
| `query_openobserve_logs` | Bounded read-only log search with SQL |
| `query_openobserve_metrics` | Bounded read-only metrics search with PromQL and optional range-query steps |
| `query_openobserve_traces` | Bounded read-only span retrieval by trace ID or custom SQL |
| `list_openobserve_streams` | Bounded read-only discovery of log, metric, and trace streams |

## Example integration flow

This walkthrough shows the integration commands you run to confirm OpenObserve is connected, and the tool calls the agent makes once it is.

### Integration commands

```bash
# List every configured integration and its source (local store or web app)
opensre integrations list

# Show the stored record for OpenObserve, including credentials shape
opensre integrations show openobserve

# Confirm the configuration has the required URL and auth before querying
opensre integrations verify openobserve
```

Example output of `opensre integrations verify openobserve`:

```
SERVICE        SOURCE      STATUS   DETAIL
openobserve    local env   passed   Configured for OpenObserve at https://openobserve.example.com
```

### Example tool calls

The four tools are invoked by the agent inside a chat session. Credentials injected from the connected integration are omitted below for brevity.

**Discover streams before querying** — `list_openobserve_streams`:

```json
{
  "org": "default"
}
```

```json
{
  "source": "openobserve",
  "available": true,
  "org": "default",
  "total_returned": 2,
  "effective_limit": 50,
  "streams": [
    {"name": "logs", "type": "logs"},
    {"name": "traces", "type": "traces"}
  ]
}
```

**Query recent error logs** — `query_openobserve_logs`:

```json
{
  "org": "default",
  "stream": "logs",
  "query": "SELECT * FROM \"logs\" WHERE level = 'error' ORDER BY _timestamp DESC",
  "time_range_minutes": 15,
  "max_results": 20
}
```

```json
{
  "source": "openobserve",
  "available": true,
  "org": "default",
  "stream": "logs",
  "total_returned": 2,
  "effective_limit": 20,
  "records": [
    {"level": "error", "message": "connection refused", "_timestamp": 1739376000000000},
    {"level": "error", "message": "timeout exceeded", "_timestamp": 1739375900000000}
  ]
}
```

**Evaluate a metric range** — `query_openobserve_metrics` (PromQL with a 30-second step):

```json
{
  "org": "default",
  "promql": "rate(http_requests_total[5m])",
  "step_seconds": 30,
  "time_range_minutes": 60
}
```

```json
{
  "source": "openobserve",
  "available": true,
  "org": "default",
  "promql": "rate(http_requests_total[5m])",
  "total_returned": 1,
  "effective_limit": 50,
  "records": [
    {
      "metric": {"__name__": "http_requests_total"},
      "values": [[1739375700, "12.5"], [1739375730, "13.1"]]
    }
  ]
}
```

**Inspect a single trace** — `query_openobserve_traces`:

```json
{
  "org": "default",
  "trace_id": "abc123",
  "stream": "traces",
  "max_results": 10
}
```

```json
{
  "source": "openobserve",
  "available": true,
  "org": "default",
  "trace_id": "abc123",
  "total_returned": 1,
  "effective_limit": 10,
  "records": [
    {"trace_id": "abc123", "span_id": "span-1", "service_name": "api", "_timestamp": 1739376000000000}
  ]
}
```

## Verify

```bash
opensre integrations verify openobserve
```

Verify is a config-shape check only — it does not call OpenObserve.

Expected output:

```
SERVICE        SOURCE      STATUS   DETAIL
openobserve    local env   passed   Configured for OpenObserve at https://openobserve.example.com
```

## Troubleshooting

| Symptom | Fix |
| --- | --- |
| **401 Unauthorized** | Regenerate the access token or confirm username/password credentials. |
| **404 on query** | Check `OPENOBSERVE_ORG` matches your organization slug. Verify `OPENOBSERVE_STREAM` and, for trace queries, `OPENOBSERVE_TRACE_STREAM`. |
| **Connection refused** | Confirm `OPENOBSERVE_URL` includes the correct protocol and port. Ensure network access from OpenSRE to the instance. |
| **Empty log results** | Widen the time range in the query. Confirm logs are ingested into the target stream. |
| **Missing credentials on verify** | Set `OPENOBSERVE_URL` and either `OPENOBSERVE_TOKEN` or both `OPENOBSERVE_USERNAME` and `OPENOBSERVE_PASSWORD`. |

## Security

Use a token with the minimum permissions required for the agent's queries whenever possible.
