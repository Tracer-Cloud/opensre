OpenSRE installs on Windows with PowerShell. You can also run the Linux install inside WSL if that's how you usually work.

## Option 1: Native Windows (PowerShell)

### 1. Install

Open PowerShell and run:

```powershell
irm https://install.opensre.com | iex
```

If a new window doesn't see `opensre`, close and reopen PowerShell so PATH updates apply.

Run `install.ps1` from PowerShell, including when you normally use Git Bash.
The bash installer stops on Windows because the Windows download contains the
complete application directory.

If an older release left `opensre.exe` directly in the install directory, the
installer shows its exact path and asks before replacing it. The default answer
is No, and declining leaves the existing file and directory unchanged. For an
unattended replacement, opt in explicitly:

```powershell
$env:OPENSRE_INSTALL_REPLACE_EXISTING_BINARY = "1"
try {
  irm https://install.opensre.com | iex
} finally {
  Remove-Item Env:OPENSRE_INSTALL_REPLACE_EXISTING_BINARY -ErrorAction SilentlyContinue
}
```

### 2. Set things up

```powershell
opensre onboard
opensre integrations setup <service>
opensre integrations verify
```

### 3. Ask the agent

Start the interactive shell:

```powershell
opensre
```

Ask: *why is checkout latency spiking?*

GIFs for Windows install and onboard are on the [Quickstart](/quickstart).

## Option 2: WSL (Linux on Windows)

Prefer a Linux shell?

1. Install [WSL](https://learn.microsoft.com/en-us/windows/wsl/install) and open your Ubuntu (or other) distro.
2. Follow the [Linux](/environments/linux-local) install guide inside that terminal.

## Stuck?

- **Command not found** — new terminal, or check that the install directory is on PATH
- **Onboard can't reach the LLM** — check the API key and network; you can save and retry later
- More tips: [Quickstart troubleshooting](/quickstart#troubleshooting)
