Use this guide when you're installing the `opensre` binary yourself — on a laptop, a shared VM, or a machine in your own network.

## Which setup fits you?

| Setup | Best for |
| --- | --- |
| **Laptop** | Trying OpenSRE, local debugging, personal use |
| **On-prem VM / server** | A shared box your team can reach |
| **Docker** | Same install every time, in a container |

## 1. Install the CLI

```bash
# Homebrew
brew tap tracer-cloud/tap
brew install tracer-cloud/tap/opensre

# or one-line installer
curl -fsSL https://install.opensre.com | bash
```

On Windows (PowerShell):

```powershell
irm https://install.opensre.com | iex
```

You usually don't need `sudo`. The installer puts `opensre` somewhere already on your PATH when it can. If it can't, it uses `~/.local/bin` and prints how to add that to PATH.

**Auto setup:** In a normal interactive terminal, install often starts `opensre setup` when it finishes. In CI or scripts it skips that. To turn auto-setup off:

```bash
curl -fsSL https://install.opensre.com | OPENSRE_AUTO_LAUNCH=0 bash
```

**GitHub CLI:** The installer also tries to install `gh` if it's missing (OpenSRE's GitHub tools need it). Skip that with:

```bash
curl -fsSL https://install.opensre.com | OPENSRE_SKIP_GH_INSTALL=1 bash
```

Homebrew installs pull in `gh` automatically.

Shorter overview: [Install OpenSRE](/install).

## 2. Sign in

```bash
opensre setup
```

The browser flow creates or signs in to your OpenSRE account with GitHub, connects the GitHub integration, and activates the hosted model. Setup opens the shell only after the webapp validates that account session.

To remain signed out, cancel setup or choose **Exit and stay signed out** when `opensre` shows the account gate. Other CLI commands remain available; the interactive shell does not.

## 3. Open the shell

```bash
opensre
```

The shell revalidates the webapp account on every start. Expired, revoked, incomplete, or unreachable account state returns to the sign-in gate instead of constructing the REPL or a model client.

#### Where credentials are saved

OpenSRE saves non-secret identity and hosted-model metadata in owner-only account metadata. The account token and GitHub credential use the local secret store; neither is written to `account.json`.

`OPENSRE_ACCOUNT_TOKEN` overrides the saved account token when set. Never commit it to `.env` or source control. Run `opensre account logout` to revoke the saved session; an environment override must be unset separately.

## 4. Check your tools

Inside the shell:

```bash
integrations verify
```

One tool only:

```bash
integrations verify datadog
```

From a normal terminal, prefix with `opensre` (for example `opensre integrations verify`).

## 5. Ask a first question

Start the shell and describe what's going on in plain English:

```bash
opensre
```

Ask: *why is checkout latency spiking?* The agent calls the tools you connected and answers in the shell.
