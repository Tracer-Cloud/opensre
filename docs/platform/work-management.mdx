## Commands at a glance

| Command | What it does |
| --- | --- |
| `/work` | List open work items |
| `/work add <title>` | Add a durable task |
| `/work edit [id-or-title]` | Choose a task and edit its current details |
| `/work done <id-or-title>` | Mark one or more tasks completed |
| `/work next` | Rank open tasks by priority, due date, and age |
| `/work path` | Print the local work-item store path |
| `opensre work ...` | Script the same workflow from the terminal |

Use `/tasks` for OpenSRE runtime jobs. Use `/work` for human todos, hackathon
work, and follow-ups. `/work add` does not schedule reminder delivery; use the
destination-aware CLI form below or ask from a connected chat.

## Natural language

You can ask normally:

```text
Add task "finish Slack reminder smoke test" for the hackathon, priority high.
```

```text
Give me an overview of all tasks that still need to be completed.
```

```text
What should I focus on next?
```

```text
Mark the docs and CLI tasks as completed.
```

The agent stores these as work items and uses the same store when ranking or
listing them later.

## Filter tasks by due date

Ask the agent to "show my overdue tasks" or "list the infra tasks due on Friday
in Asia/Kolkata." The `work_task_list` agent tool accepts these optional filters:

| Value | Default | Behavior |
| --- | --- | --- |
| `due_after` | Unset | Include tasks due at or after this ISO date/time. |
| `due_before` | Unset | Include tasks due strictly before this ISO date/time. |
| `overdue_only` | `false` | Include only unfinished tasks due strictly before the current instant. |
| `timezone` | `UTC` | IANA timezone for date-only or offset-free bounds and stored due dates. Used when a due filter is active. |

For example, this tool input selects tasks due on 30 October in Kolkata:

```json
{
  "project": "infra",
  "due_after": "2026-10-30",
  "due_before": "2026-10-31",
  "timezone": "Asia/Kolkata"
}
```

A date without a time means midnight at the start of that date. Explicit UTC
offsets such as `2026-10-30T09:00+05:30` identify an instant directly. A local
time that does not exist during a daylight-saving transition is rejected;
an ambiguous time requires an explicit offset. If both bounds are given,
`due_after` must precede `due_before`.

Due filters combine with the existing status, project, and owner filters before
the result limit; `total` counts all matching tasks. The default status remains
`open`. Use `status: "active"` to include blocked and deferred tasks too.
Completed tasks are always excluded by `overdue_only`, even with `status: "all"`.

Undated tasks are excluded when a due filter is active. Dates that cannot be
resolved are excluded and counted in `invalid_due_dates` among the otherwise
matching tasks. The response's `due_filter` records the resolved UTC bounds,
timezone, and the cutoff used for overdue checks. Without a due filter, the
existing listing behavior and response fields are unchanged. These options
belong to the agent tool; terminal commands retain their existing options.

## Reminders and check-ins

One-off reminders:

```bash
opensre work add "ping owners about demo blockers" \
  --project hackathon --priority high \
  --remind-at 2026-07-30T09:30 \
  --provider slack --chat-id C0123ABCD
```

Recurring check-ins:

```bash
opensre work schedule-checkin \
  --cron "0 9 * * mon-fri" \
  --tz Europe/London \
  --target slack:C0123ABCD \
  --target telegram:-100123456 \
  --project hackathon
```

Slack, Telegram, and Discord gateway turns can default reminders and recurring
check-ins to the current chat. Terminal commands require either `--provider` and
`--chat-id`, or one or more `--target` flags.
Use repeated `--target provider:chat_id` flags to send the same reminder or
check-in to more than one service. Slack webhook delivery may use `--target
slack` without a channel id; Telegram, Discord, and Rocket.Chat need explicit
chat/channel ids.

## Storage

Work items are stored locally as JSON under `~/.opensre/work_items/` by default.
Set `OPENSRE_WORK_ITEMS_DIR` to choose another folder. Existing entries from the
old Slack captured-task JSONL store are imported once into the new work-item
store.

Recurring check-ins are stored in OpenSRE's scheduler store and run whenever the
gateway scheduler or `opensre cron start` is active.
