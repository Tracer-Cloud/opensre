## What is OpenSRE?

OpenSRE is an open-source agent that answers production questions for you. When an alert comes in — or you just tell it something's wrong — it goes and checks: recent deploys, logs, metrics, whatever's connected. Then it tells you what it found.

**Who's it for?** Anyone on call who's tired of starting from a blank tab at 3am. It's built for engineers who want a head start on the cause, not a black box that hides how it got there.

**Why people like it:**

- It works with what you already have — no need to rip out your existing stack
- You can run it locally, in your terminal, or hook it into a hosted setup for your whole team
- It's open source, so you can see exactly what it's doing and change it if you need to

**What do you need to get going?** An OpenSRE account, access to the tools you want to connect, and about five minutes. The [Quickstart](/quickstart) walks through it.

## Try it now

<Steps>
  <Step title="Install">
    One command and you're done — no dependencies to wrangle first.

    ```bash
    curl -fsSL https://install.opensre.com | bash
    ```
  </Step>
  <Step title="Set things up">
    This opens the OpenSRE sign-up page. Create an account or sign in using email or another enabled provider; OpenSRE then activates the hosted model. Add tools later with `opensre integrations setup <service>` when you want it to query GitHub, Datadog, Grafana, Slack, or another system.

    ```bash
    opensre setup
    ```
  </Step>
  <Step title="Give it something to look at">
    Open the shell with no arguments and describe what's going on in your own words — or paste the alert body straight in:

    ```bash
    opensre
    ```
  </Step>
</Steps>

<Tip>
  Something not working? [Quickstart troubleshooting](/quickstart#troubleshooting) covers account validation and install issues.
</Tip>

## How a turn runs

Say an alert fires and you paste it in. Here's roughly what happens next:

1. OpenSRE reads the alert and figures out what kind of problem it's looking at
2. It gathers context — who owns the service, what changed recently, what's normal
3. It goes and checks the tools you've connected for logs, metrics, and traces
4. It keeps digging and testing ideas until it can answer
5. It answers in the shell, and sends the result wherever you asked — Slack, Telegram, a file
