## Before you begin

Make sure you have:

- A terminal open in a code project
- A Git repository (recommended for the full workflow demonstration)

## Step 1: Install and start opensre

```bash
curl -fsSL https://install.opensre.com | bash -s -- -dc
```

Then start OpenSRE:

```bash
opensre
```

![OpenSRE CLI welcome screen with the sign-in prompt](/images/opensre-welcome.png)

On Windows, open PowerShell and run:

```powershell
& ([scriptblock]::Create((irm https://install.opensre.com/install.ps1))) -dc
```

See [Windows](/install/windows-local).

You usually don't need `sudo`. The installer uses a writable directory on your PATH when it can. Otherwise, it uses `~/.local/bin` and prints how to add that to PATH.

For platform requirements, see [macOS](/install/macos), [Linux](/install/linux-local), or [Windows](/install/windows-local). For a container, see [Docker](/install/docker).

## Step 2: Sign in

Choose **Sign in or create account** in the welcome screen. Your browser opens the OpenSRE sign-up page; sign in with email or another enabled provider. Signing in activates the hosted model, so you need no LLM key. Back in the terminal, OpenSRE confirms the session with the web app, opens the shell and offers the [demos](/getting-started/quickstart#step-3-pick-a-demo-or-skip-it); choose **E** to go straight to the prompt. If the sign-in screen comes back instead, `opensre account status` names what is wrong with the session.

## Step 3: Check your tools

Inside the shell:

```bash
integrations verify
```

One tool only:

```bash
integrations verify datadog
```

From a normal terminal, prefix with `opensre` (for example `opensre integrations verify`).

## Step 4: Ask a first question

Start the shell and describe what's going on in plain English:

```bash
opensre
```

Ask: *why is checkout latency spiking?* The agent calls the tools you connected and answers in the shell.

## Where to connect tools

The full tool list lives under **Integrations**, not Install.

Start at [Integrations overview](/integrations), then open each provider page for keys, permissions, and examples.
