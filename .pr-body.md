## Summary

`resolve_effective_integrations()` drops a Datadog integration configured **only through environment variables** (`DD_API_KEY` / `DD_APP_KEY` / `DD_SITE`), and loses a non-default site such as `datadoghq.eu`.

`datadog` is not in `DIRECT_CLASSIFIED_EFFECTIVE_SERVICES`, so it is resolved by a dedicated fallback that read the first raw record from `record_by_service["datadog"]`. That map is populated only by the **store** and **remote** loops, never the **env** loop, so an env-only Datadog was never published and its site defaulted to `datadoghq.com`.

`classify_integrations(load_env_integrations())` resolves the same Datadog correctly, which hides the bug: the agent path works while `resolve_effective_integrations()` — used by `opensre integrations verify`, tool `is_available()` checks, etc. — returns nothing for an EU (or any env-only) Datadog.

## Fix

Resolve Datadog from the **classified** config first, via `_publish_classified_effective_service`, the same way `DIRECT_CLASSIFIED_EFFECTIVE_SERVICES` are published. The classified view already merges env/store/remote, so env-only Datadog (including a non-default `DD_SITE`) now resolves. It also validates per instance, so for multi-instance `DD_INSTANCES` it selects a **complete** instance instead of publishing the first raw record's (possibly empty) keys.

The existing raw-record fallback is kept as a **secondary** step that runs only when classification produced nothing. This preserves the current behaviour of surfacing a lone incomplete store record as configured-but-incomplete (`test_resolve_effective_integrations_keeps_incomplete_datadog_store_record`) rather than dropping it. Because it runs after the classified publish, it can never override a valid instance selected above.

## Test

- `test_resolve_effective_integrations_publishes_env_configured_datadog` — env-only Datadog with `DD_SITE=datadoghq.eu` resolves with the correct site and keys (next to the prefect regression test).
- `test_resolve_effective_integrations_datadog_multi_instance_skips_incomplete` — a multi-instance record whose first instance is missing `app_key` resolves to the valid later instance.

`tests/integrations/test_verify.py` and `test_catalog_multi_instance.py` pass unchanged (60 tests).
